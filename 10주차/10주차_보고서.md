# [컴퓨터 네트워크 팀 프로젝트] 10주차 주간 보고서

- **프로젝트명**: 멀티스레드 기반 고성능 HTTP 프록시 및 LRU 캐싱 서버 구현
- **작성 주차**: 10주차 (4인 역할별 핵심 모듈 1차 구현 및 단위 검증)
- **개발 환경**: Python 3 (표준 라이브러리 `socket`, `threading` 등 전용)

---

## 1. 금주(10주차) 목표

1. 9주차에 수립한 4인 역할 분담(A·B·C·D)에 따라 각 담당 모듈의 **1차 핵심 기능 구현**을 완료한다.
2. 개별 모듈 단위 테스트를 수행하고, 차주 통합을 위한 **모듈 간 인터페이스 및 동시성 규칙**을 정리한다.

---

## 2. 역할별 주요 수행 내용

### 2.1 역할 A — 네트워크 소켓 코어 (`proxy.py`)
- TCP 바이트 스트림에서 헤더 끝(`\r\n\r\n`)과 `Content-Length` 본문 길이를 기준으로 HTTP 요청을 수신하는 `recv_request()` 구현
- 프록시 요청(`GET http://host/path`)을 Origin 서버 규격(상대 경로 + `Connection: close`)으로 변환하는 `build_upstream_request()` 구현
- 잘못된 요청(`400`), 미구현 `CONNECT`(`501`), 업스트림 연결 실패(`502`), 타임아웃(`504`) 에러 응답(`send_error()`) 및 단일 접속 릴레이 구현

### 2.2 역할 B — HTTP 프로토콜 파서 및 필터 (`http_parser.py`)
- 수신된 원시 HTTP 요청 바이트에서 Request-Line을 파싱해 `method`, `host`, `port`, `url`, `is_blocked`를 반환하는 `parse_http_request()` 구현
- `set` 자료구조 기반 $O(1)$ 검색으로 유해 사이트(`warning.or.kr`, `game.com`, `gambling.com`)를 판별하는 `BLACKLIST` 필터 구현

### 2.3 역할 C — 바이트 기반 LRU 캐시 엔진 (`lru_cache.py`)
- 해시맵(`dict`)과 이중 연결 리스트를 결합해 `get()` / `put()` 모두 $O(1)$에 동작하는 바이트 용량 제한 `LRUCache` 구현
- URL 키 정규화 함수(`make_key`, `key_from_url`) 및 단일 항목 크기 상한(`max_item_bytes`)·LRU 축출 로직 구현
- `GET`·`200 OK` 허용, `no-store`/`private`/`no-cache`·`Set-Cookie` 제외, `Content-Length`/`chunked` 완전성을 검사하는 `is_cacheable()` 구현

### 2.4 역할 D — 다중 접속 제어 및 Lock 동기화 (`role_d_concurrency.py`)
- 클라이언트 접속마다 워커 스레드(`threading.Thread`)를 생성해 요청을 병렬 처리하고, `BoundedSemaphore`로 최대 동시 스레드 수를 제어하는 `MultiThreadedProxyServer` 구현
- `cache_lock`과 `stats_lock`을 분리해 `LRUCache`의 `get()`/`put()` 접근 시 경쟁 상태와 교착 상태를 방지하는 `ThreadSafeSynchronizer` 구현
- A·B·C 원본 모듈을 수정 없이 연결하는 요청 처리 파이프라인 및 종료 시 스레드 정리 대기(Graceful Shutdown) 구현

## 3. 10주차 개별 모듈 단위 테스트 결과

### 3.1 역할 A (`proxy.py`)
- **요청 대상 파싱(`parse_target`)**: `GET http://example.com:80/index.html HTTP/1.1` 입력 시 `('GET', 'example.com', 80, '/index.html', 'HTTP/1.1')` 정상 분리 확인
- **Origin 요청 변환(`build_upstream_request`)**: 프록시 전용 헤더(`Proxy-Connection: keep-alive`) 제거, 절대 URL을 상대 경로(`/index.html`)로 치환, `Connection: close` 헤더 자동 추가 확인

### 3.2 역할 B (`python http_parser.py`)
- **정상 사이트 파싱**: `GET http://example.com/ HTTP/1.1` 입력 시 `{'method': 'GET', 'host': 'example.com', 'port': 80, 'url': 'http://example.com/', 'is_blocked': False}` 반환 확인
- **블랙리스트 필터링**: `GET http://game.com/play HTTP/1.1` 입력 시 `host: 'game.com'`, `is_blocked: True`로 정상 차단 판별 확인

### 3.3 역할 C (`python lru_cache.py` — 8개 테스트 그룹 전원 `[PASS]`)
- **LRU 축출 및 바이트 용량 제한**: `a/b/c` 저장 후 `a` 조회 시 가장 오래된 `b` 우선 축출(`["a", "d", "c"]`), 큰 항목(`25 B`) 삽입 시 기존 다수 항목 동시 축출, `max_item_bytes` 초과 항목 저장 거부(`False`) 및 기존 캐시 유지 확인
- **키 정규화(`make_key` / `key_from_url`)**: 대소문자, 기본 포트(`:80`), 호스트 끝 점(`.`), `#fragment`, IPv6 주소에서 두 함수 결과 일치 확인 및 `https://`·잘못된 포트 등 비정상 URL의 `None` 반환 확인
- **캐시 정책(`is_cacheable`)**: `GET 200 OK`·`max-age`·종료 시퀀스(`0\r\n\r\n`)가 완전한 `chunked` 응답만 허용하고, `POST`·`404`·`no-store`·`Set-Cookie`·본문 길이가 잘린 응답은 모두 거부 확인
- **내부 일관성**: 20회 반복 `put`/`get` 후 `dict`와 이중 연결 리스트 항목 수 일치, `bytes_used <= max_bytes`, `hits + misses == 20` 검증 완료

### 3.4 역할 D (`role_d_concurrency.py`)
- **멀티스레드 Lock 동시성 검증**: `ThreadSafeSynchronizer`에 16개 워커 스레드가 동시에 `safe_cache_put()`과 `safe_cache_get()`을 각 20회(총 320회 `put` + 320회 `get`, `max_bytes=200`) 수행
- **검증 결과**: Race Condition·연결 리스트 손상·예외 발생 `0건`, 캐시 사용량 상한(`bytes_used: 200 / max_bytes: 200`, `items: 5`, `evictions: 300`, `hits: 320`) 일관성 유지 확인

## 4. 주요 이슈 및 설계 검토 사항

1. **모듈 간 인터페이스 합의 사항**
   - 캐시 키 방식을 `(가) B dict에 path 추가 후 make_key()`와 `(나) 기존 url 그대로 key_from_url()` 중 하나로 통일할 필요가 있으며, 우선 `(나)`를 기본으로 연동하기로 정리했다.
   - 역할 B 블랙리스트에서 대문자(`GAME.COM`), `www.` 서브도메인, 끝의 점(`game.com.`) 우회 가능성을 확인해 차주 보완 과제로 정리했다.
2. **LRU 조회(`get`) 연산의 Lock 보호**
   - `LRUCache.get()`도 적중 시 노드를 최근 위치(MRU)로 이동시키는 쓰기 연산이므로 `put()`과 함께 `cache_lock`으로 보호하도록 동기화 구조를 확정했다.
